# FileWorker SFTP 客户端设计规范

## 1. 目标

构建一个面向 macOS 的桌面文件传输客户端，提供类似 Xftp 的使用体验：

- 并排浏览本地目录和远程目录。
- 连接 SFTP 服务器。
- 将本地文件拖到远程目录中上传。
- 将远程文件拖到本地目录或 Finder 中下载。
- 显示传输进度，支持取消、重试和断点续传。
- 让协议层和传输层保持可移植，便于以后支持其他桌面平台和协议。

第一版只支持 SFTP。FTP/FTPS、SCP、WebDAV 和 S3 作为后续协议适配器，
不属于第一版范围。

## 2. 产品范围

### 第一版包含

- macOS 桌面应用。
- 连接配置，包含：
  - 连接名称。
  - 主机地址。
  - 端口，默认 `22`。
  - 用户名。
  - 密码认证。
  - SSH 私钥认证和私钥口令。
  - 连接后的默认远程目录。
- 本地和远程双栏文件浏览。
- 目录进入、返回、刷新、排序和路径输入。
- 单文件和多文件上传、下载。
- 双栏之间以及与 Finder 之间的拖拽。
- 传输队列，包含：
  - 进度。
  - 速度和预计剩余时间。
  - 暂停、取消、重试。
  - 每个任务的错误信息。
  - 可配置并发数，默认 `3`。
- 覆盖、跳过和重命名等冲突处理方式。
- 临时文件处理和可恢复传输。
- SSH 主机指纹确认和变化检测。
- 使用 macOS Keychain 保存密码和私钥口令。
- 打包 macOS `.app` 应用。

### 明确不属于第一版

- 远程文件编辑。
- 文件夹同步规则。
- 脚本自动化。
- 共享连接配置。
- 多窗口工作流。
- SFTP 以外的协议。

## 3. 推荐技术方案

使用 Tauri 2、React/TypeScript 前端和 Rust 后端。

### 选择这个方案的原因

- 前端适合实现文件管理器布局、拖拽、进度视图、菜单和快捷键。
- Rust 负责安全敏感和并发敏感的传输逻辑。
- Tauri 让应用具备跨平台基础，同时可以先专注于 macOS 版本。
- 协议层和传输层不依赖具体的界面框架。

### 其他方案

- 纯 Rust 界面可以减少语言种类，但要为成熟的 macOS 文件管理器交互
  自行完成更多工作。
- SwiftUI 界面加 Rust 核心可以获得很好的 macOS 原生体验，但会引入
  FFI 边界，未来扩展到其他平台的成本更高。

## 4. 系统架构

应用分成五个逻辑层：

### `frontend`：前端界面层

职责：

- 连接管理界面。
- 本地和远程文件栏。
- 拖拽操作。
- 文件选择、菜单、对话框和快捷键。
- 传输队列展示。

前端不持有 SSH 连接，也不实现传输重试或断点续传逻辑。

### `app`：应用协调层

职责：

- Tauri 命令处理器。
- 应用状态和会话生命周期管理。
- 将前端请求映射为领域操作。
- 向前端发送传输进度和状态事件。

### `transfer`：传输层

职责：

- 任务排队和调度。
- 上传、下载流程编排。
- 取消和暂停状态。
- 重试策略。
- 并发限制。
- 临时文件和断点续传处理。

### `protocol`：协议层

职责：

- 提供与具体协议无关的远程文件操作。
- 管理连接生命周期。
- 实现目录列表、文件信息查询、创建目录、重命名、删除、上传和下载。

第一版的具体实现是 `SftpBackend`。未来的其他协议适配器实现同一套
精简接口，不需要修改前端。

### `storage`：存储层

职责：

- 保存非敏感的连接配置。
- 保存最近使用的本地和远程路径。
- 访问 Keychain 保存密码和私钥口令。
- 保存已确认的主机指纹。

## 5. 核心领域模型

以下模型与具体协议无关：

### `ConnectionProfile`：连接配置

包含配置标识、主机、端口、用户名、认证方式、私钥路径和默认远程目录。
敏感信息通过安全存储引用，不直接写入配置对象。

### `RemoteEntry`：远程目录项

表示一个远程文件或目录，包含名称、路径、类型、大小、修改时间和可用的
权限信息。

### `TransferJob`：传输任务

包含源路径、目标路径、传输方向、连接标识、冲突策略、续传策略和用户可见
的显示信息。

### `TransferState`：传输状态

状态包括：

- 等待中。
- 传输中。
- 已暂停。
- 已完成。
- 失败。
- 已取消。

## 6. 主要数据流

1. 用户拖拽一个或多个文件。
2. 前端创建 `TransferJob` 描述。
3. Tauri 命令将任务提交到 Rust 传输队列。
4. 队列在并发限制内选择一个工作任务。
5. 选中的协议后端执行传输。
6. 传输工作线程发送进度、状态和错误事件。
7. 前端更新传输队列和文件列表。
8. 任务成功后刷新目标目录。

一个任务失败时，队列仍然必须可用。失败任务应独立记录状态，用户可以
单独重试，不需要重启应用，也不会取消其他任务。

## 7. 安全性和可靠性

### 凭据

- 将密码和私钥口令保存到 macOS Keychain。
- 普通配置文件只保存非敏感的连接元数据。
- 日志中不得记录密码、私钥内容或包含凭据的完整 URL。

### 主机校验

- 首次连接时显示 SSH 主机指纹。
- 用户明确确认后，才信任新的主机指纹。
- 已保存的主机指纹发生变化时，阻止连接并显示清晰警告。

### 文件安全

- 目标文件已存在时必须确认处理方式，不允许静默覆盖。
- 传输先写入临时目标文件，完成后再重命名。
- 保存足够的元数据，以便恢复中断的传输。
- 执行传输前规范化并校验本地路径和远程路径。

### 网络故障

- 在有限重试次数内自动重试临时性错误。
- 保留每个任务的失败状态和原因。
- 支持手动重试和取消。
- 单个任务失败不能阻止队列中的其他任务。

### 暂停语义

- 暂停正在执行的任务时，在安全的传输边界停止，并保留临时目标文件和
  续传元数据。
- 恢复暂停任务时，创建新的传输会话，从已记录的位置继续，不长期保持
  空闲 SSH 连接。

## 8. 界面结构

### 连接管理

首屏显示已保存的连接配置，并提供新建、编辑、复制、删除和连接操作。

### 主工作区

- 左栏：本地文件浏览器。
- 右栏：远程 SFTP 文件浏览器。
- 每个文件栏都包含路径控件、导航操作、刷新、排序和选择功能。
- 底部传输区域可以展开或收起。

### 拖拽操作

- 本地拖到远程：上传。
- 远程拖到本地：下载。
- 远程拖到 Finder：下载到 Finder 指定位置。
- Finder 拖到文件栏：根据目标文件栏执行上传或本地复制。

界面必须显示明确的可放置区域状态；对于不支持的拖拽，应拒绝创建无效的
传输任务。

## 9. 测试和验证

### Rust 单元测试

- 传输状态转换。
- 重试策略。
- 冲突处理策略。
- 路径规范化。
- 队列并发限制。
- 断点续传决策逻辑。

### 协议集成测试

使用本机 OpenSSH/SFTP 服务验证：

- 密码认证。
- 私钥认证。
- 远程目录列表和导航。
- 上传和下载。
- 中断后的传输恢复。
- 主机指纹变化处理。

### macOS 手工验收

- 将本地文件拖入远程文件栏。
- 将远程文件拖入本地文件栏和 Finder。
- 上传和下载多个文件。
- 取消并重试传输。
- 关闭并重新打开应用，确认连接配置仍然存在。
- 构建并启动 macOS `.app`。

## 10. 交付阶段

1. 安装 Rust stable、macOS 编译工具、Node.js 和 pnpm。
2. 创建 Tauri 应用骨架和项目目录结构。
3. 实现连接配置和安全凭据存储。
4. 实现本地和远程文件浏览。
5. 实现 SFTP 上传和下载。
6. 加入拖拽操作和传输队列。
7. 加入断点续传、重试、主机校验和冲突处理。
8. 运行测试，完成 macOS 验收，并打包 `.app`。

## 11. 已确认的决策和假设

- 第一版平台是 macOS。
- 跨平台是设计目标，但不是第一版的验收要求。
- 第一版只支持 SFTP。
- 默认传输并发数为 `3`，并且可以配置。
- 第一版同时支持密码和私钥认证。
- 默认界面语言为中文，同时保留后续国际化的结构。
