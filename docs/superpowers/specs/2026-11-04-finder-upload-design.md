# Finder 文件拖入上传

## 已确认范围

用户于 2026-11-04 确认：实现 Finder 单个/多个普通文件拖入远程文件栏上传，
复用现有传输队列与冲突处理，并保留双栏内部拖拽。

本阶段不实现 Finder 拖出、本地复制、目录拖入、递归传输、暂停/续传、跨重启恢复
或 GitHub Release。只把 macOS Apple Silicon 列为当前验收目标；Windows/Linux
仍需单独构建、运行和原生拖放验收。

## 原生事件

主窗口配置 `dragDropEnabled: true`，由 Tauri 2 提供当前 WebView 的原生文件拖放事件。
不安装自定义 WKWebView 子类，不改 Wry 全局方法，不保存原生 ticket，也不新增
任意路径读取 IPC。

`src/lib/api.ts` 使用 Tauri 官方通用 `listen` API，分别监听：

- `tauri://drag-enter`
- `tauri://drag-over`
- `tauri://drag-drop`
- `tauri://drag-leave`

监听目标绑定当前 WebView。Tauri 事件中的位置是相对 WebView 左上角的物理像素，
API 按当前窗口尺寸和 `devicePixelRatio` 转成 `0..1` 的归一化坐标；离开事件使用
无效坐标，避免误命中。监听卸载时解除四个事件，异步注册晚于组件卸载也不会泄露。

Rust 的 `get_environment` 只在 macOS 返回 `finderDrop: true`。浏览器预览和其他
尚未验收的平台不注册 Finder 入口；按钮传输和现有会话逻辑不依赖 Finder 入口。

## 前端与队列

`useFinderDrop` 独立管理原生事件、目标命中和生命周期：

- 只有存在当前 SSH 会话、本地和远程目录列表，且没有连接弹窗或其他阻塞状态时才接受。
- 进入事件记录路径批次、会话和两栏列表对象；只有实际命中远程文件列表且没有其他
  元素遮挡时才高亮。
- 放下时必须仍是同一批路径、同一会话和同一份已打开目录列表；同一原生拖动只提交一次。
- Escape、刷新、导航、断开、重连、内部拖动开始、提交中和组件卸载都会使旧手势失效。
- 远程路径输入框的未提交内容不改变目标，上传始终使用最后成功打开的远程目录。

Finder 上传与按钮、双栏内部拖放共用 `useTransfers` 的提交互斥、队列刷新、错误提示、
取消、重试和冲突处理。

## Rust 校验

`enqueue_finder_upload(paths, session_id, destination_dir)` 在后台线程中先校验整批路径，
所有项目通过后才构造现有 `TransferRequest` 并进入 `TransferManager`：

- 批次必须包含 1 到 256 个路径；
- 路径必须是绝对路径、长度不超过 32768，且不含控制字符；
- 不允许重复路径、缺失路径、目录、符号链接或其他特殊文件；
- 任一项目失败时整批拒绝，不创建任何队列任务，也不修改源文件。

传输执行阶段仍由现有 SFTP 传输逻辑检查源文件变化、目标冲突、临时文件和 SHA-256
相关验收约束；Finder 入口不放宽主机验证、覆盖策略或队列限制。

## 验收与限制

- 前端行为测试覆盖目标命中、路径输入、重复放下、无进入、Escape、刷新/导航、断开
  重连、提交互斥、弹窗遮挡、预览和异步卸载。
- Playwright 覆盖明暗主题、1280/800 宽度、物理像素事件坐标、错误目标和重复放下；
  不能替代真实 Finder。
- Rust 单元测试覆盖批次大小、绝对路径、重复、普通文件、目录、符号链接和缺失文件。
- 开发版 `.app` 已成功构建；真实 Finder 多文件上传、混入目录/符号链接拒绝和同名
  保留两份需要在解锁的 macOS Apple Silicon 环境完成。

不触碰用户真实 SSH 密钥、系统 `known_hosts` 或真实凭据。回退前应停止传输并退出应用；
已经上传的文件不会自动回滚。本阶段不创建标签或 Release。
