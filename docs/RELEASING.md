# FileWorker 发布计划

当前状态：已提供 `v0.1.0-preview.1` macOS Apple Silicon 实验性预发布，
本轮 `v0.1.0-preview.2` 已完成优化构建、打包及原生冒烟验收，按新标签分发。
尚无正式 Release；预发布包未使用 Apple Developer ID 分发签名、未公证，不能视为稳定发行版。

## 近期顺序

1. 源码、测试、锁文件、文档及 MIT 许可证已同步 GitHub，排除本机与敏感数据；
   后续修复按独立提交同步，不重写已有历史。
2. Finder 拖入普通文件到远程栏的代码、队列复用、整批校验和浏览器边界测试已完成。
   2026-11-05 在发布包上实测真实 Finder 多文件上传、同名保留两份和 SHA-256；
   混合无效批次完整证据仍待补齐。双栏拖拽、Finder 拖入和拖出仍分别验收，
   不将浏览器拖拽测试当作原生验收，详见 `docs/acceptance/2026-11-05-native-transfers.md`。
3. 设计并验证暂停/恢复、续传元数据和异常退出后的恢复；在完成前仍明确标为不支持。
4. `v0.1.0-preview.1` 已提供 macOS Apple Silicon `.app.zip` 和 SHA-256。
   当前源码增加同名自动弹框，以 `v0.1.0-preview.2` 新标签分发，不替换旧标签或产物；
   这些实验包仍未使用 Apple Developer ID 分发签名、未公证。
5. 建立独立于发布权限的持续集成；安装、升级、签名、公证与安全验收通过后，才确定
   首个正式版本。

目录递归传输另行设计与验收，不顺带启用未经验证的递归覆盖、符号链接或自动删除。
不为赶发布而放宽主机验证、明文保存凭据或移除 `libssh2-sys` 的安全补丁固定。

## 下载产物

当前实验性预发布目标是 macOS Apple Silicon，提供便于下载的 `.app.zip`。
首个正式发行目标仍是 macOS Apple Silicon，后续可再提供磁盘映像或压缩包。
Intel Mac 需单独构建并验收后再列为支持；Windows/Linux 不在首版承诺范围内。
版本号、架构、最低 macOS 版本、签名状态和已知限制必须在下载页面写清楚。

这不是架构上只能支持 macOS。Windows/Linux 桌面需另行完成系统凭据、
本地与远程路径语义、构建入口、窗口/拖放和平台打包适配，再在目标环境实测。
具有桌面环境不等于依赖已经齐全；完成前不把这些平台列为已支持，不提供未经验证的安装包。

安装包放在 GitHub Releases，不放进源码分支。每次分发包含：

- 指向确切提交的版本标签与对应源码。
- 每个实际支持架构的安装包，避免用同一文件冒充通用二进制。
- SHA-256 校验文件、变更记录、已知问题和回退说明。
- 项目许可证与所分发第三方依赖的必要许可说明。

## 自动化边界

持续集成先运行 Rust、真实隔离 SFTP、前端、类型、格式和 Clippy 检查；
界面测试使用 Playwright，不能替代 macOS 原生 Finder 拖拽和安装验收。Finder
拖入依赖 Tauri 的 `dragDropEnabled: true` 与当前 WebView 事件；Windows/Linux
需要独立验证原生拖放和 HTML5 双栏拖放的兼容性。
发布工作流与普通验证分开，后续只对明确的版本标签构建，默认先创建草稿或预发布。
发布凭据仅在 GitHub 的受控环境中配置，不写入仓库、工作流明文、构建日志或安装包。

正式发布前再决定 Developer ID 签名、公证和相应凭据管理方式。
未使用 Developer ID 签名、未公证的测试包必须明确标为实验性预发布，不能宣称没有
系统安全提示。
当前不新增证书、密钥、账户配置或自动更新服务。
