# FileWorker 发布计划

当前状态：仅规划，尚无正式 Release。此文档不触发构建、创建标签、上传安装包或发布版本。

## 近期顺序

1. 已完成源码基线 `877aa32` 的 GitHub 同步，包含测试、锁文件、文档及 MIT 许可证，
   排除本机与敏感数据；后续修复按独立提交同步，不重写已有历史。
2. 继续既定产品设计中的拖拽工作流，复用现有传输队列、冲突处理和主机验证。
   双栏拖拽、Finder 拖入和拖出到 Finder 分别验收，不将浏览器拖拽测试当作原生验收。
3. 设计并验证暂停/恢复、续传元数据和异常退出后的恢复；在完成前仍明确标为不支持。
4. 建立独立于发布权限的持续集成，再准备首个 macOS 预发布安装包。
5. 安装、升级、签名与安全验收通过后，才确定首个正式版本。

目录递归传输另行设计与验收，不顺带启用未经验证的递归覆盖、符号链接或自动删除。
不为赶发布而放宽主机验证、明文保存凭据或移除 `libssh2-sys` 的安全补丁固定。

## 下载产物

首个发行目标是 macOS Apple Silicon，提供便于安装的磁盘映像或压缩包。
Intel Mac 需单独构建并验收后再列为支持；Windows/Linux 不在首版承诺范围内。
版本号、架构、最低 macOS 版本、签名状态和已知限制必须在下载页面写清楚。

这不是架构上只能支持 macOS。Windows/Linux 桌面需另行完成系统凭据、
本地与远程路径语义、构建入口、窗口/拖放和平台打包适配，再在目标环境实测。
具有桌面环境不等于依赖已经齐全；完成前不把这些平台列为已支持，不提供未经验证的安装包。

安装包放在 GitHub Releases，不放进源码分支。每次分发包含：

- 指向确切提交的版本标签与对应源码。
- 每个实际支持架构的安装包，避免用同一文件冒充通用二进制。
- SHA-256 校验文件、变更记录、已知问题和回退说明。
- 项目许可证与所分发第三方依赖的必要许可说明。

## 自动化边界

持续集成先运行 Rust、真实隔离 SFTP、前端、类型、格式和 Clippy 检查；
界面测试使用 Playwright，不能替代 macOS 原生拖拽和安装验收。
发布工作流与普通验证分开，后续只对明确的版本标签构建，默认先创建草稿或预发布。
发布凭据仅在 GitHub 的受控环境中配置，不写入仓库、工作流明文、构建日志或安装包。

正式发布前再决定 Developer ID 签名、公证和相应凭据管理方式。
未签名公证的测试包必须明确标为实验性预发布，不能宣称没有系统安全提示。
当前不新增证书、密钥、账户配置或自动更新服务。

## 首次发布检查

- [ ] 产品功能与 README 中的承诺一致，未实现能力明确列出。
- [ ] 从干净检出与锁文件可重复安装依赖并完成优化构建。
- [ ] Rust、隔离协议、前端、类型、格式、Clippy、界面与必要的内存检查通过。
- [ ] 原生验证真实上传下载、冲突、取消、断开和退出，不使用真实用户凭据。
- [ ] 在目标 macOS 与架构上实测安装、首次打开、重开、升级和回退。
- [ ] 最低系统版本、权限、签名与公证状态有实际证据。
- [ ] 安装包不包含开发机路径、测试账号、私钥、连接配置或调试日志。
- [ ] 标签、版本号、提交、安装包、校验文件和发布说明相互对应。
- [ ] 用户明确确认后再创建 Release；本次代码同步不执行发布。
