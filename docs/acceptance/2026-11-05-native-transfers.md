## 环境与隔离

- 平台：macOS `26.5.2`（`25F84`），Apple M5 Pro，`arm64`。
- 服务：仅监听 `127.0.0.1` 的仓库 AsyncSSH 夹具，使用生成的测试文件和一次性凭据。
- 应用：独立 HOME；不访问实际服务器、用户 SSH 私钥或应用的实际连接配置；
  不保存测试密码到 Keychain。
- 初轮测试目录为已忽略的 `target/native-finder-acceptance/`，混合批次补验使用
  `target/native-finder-mixed-acceptance/`；两轮结束后均已删除，不提交测试账号、
  密钥、日志、快照或产物。

## 同名自动弹框

本次源码的 macOS debug `.app` 使用相同隔离服务，通过原生上传按钮提交两文件，
不以此替代 Finder 入口验收。实测首个真实同名自动弹框，保留两份后自动提示第二个；
第二个关闭后保持待处理，刷新目录未重弹；从队列重新打开并保留两份成功。
生成的 `(2)` 副本与上表对应源文件 SHA-256 一致，原件未变，无临时文件遗留。

自动化补充：完整 `107` 项前端测试、`19` 项 Playwright、类型检查及生产前端构建通过。
覆盖关闭按钮、Escape、遮罩、重复快照、多个冲突、延后处理、重复点击、提交失败、
断开和新尝试、其他弹窗阻塞；检查明暗主题的 1280、800、390 像素视口。

## 混合无效批次补验

使用上节相同 SHA-256 的 `v0.1.0-preview.2` 发布 ZIP 解压副本，不修改应用代码。
新建隔离 HOME、回环 SFTP 服务、空目标目录 `/native-check` 和全新源文件，避免此前
已上传文件干扰判断。符号链接指向另一份生成的普通文件，文件系统 `lstat` 确认为
符号链接。一次自动跨应用拖拽没有送达，不计入验收；以下三次均由用户从 Finder
真实拖入并确认，未调用上传 IPC 或注入拖放事件。

以下时间均为 2026-11-05，Asia/Shanghai（UTC+8）。每次手势前后分别检查原生队列、
远端完整目录清单、源文件大小与 SHA-256，并在现有 AsyncSSH 夹具外层审计文件操作：
