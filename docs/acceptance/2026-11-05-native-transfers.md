# macOS 原生传输验收 · 2026-11-05

## 环境与隔离

- 平台：macOS `26.5.2`（`25F84`），Apple M5 Pro，`arm64`。
- 服务：仅监听 `127.0.0.1` 的仓库 AsyncSSH 夹具，使用生成的测试文件和一次性凭据。
- 应用：独立 HOME；不访问实际服务器、用户 SSH 私钥或应用的实际连接配置；
  不保存测试密码到 Keychain。
- 测试目录在已忽略的 `target/native-finder-acceptance/`，不提交测试账号、密钥或产物。

## 已发布包的真实 Finder 验收

测试产物为下载的 `FileWorker-v0.1.0-preview.1-macos-arm64.app.zip`，没有修改其代码。
ZIP SHA-256：

```text
0f3138fcb758751179f3b81f9df0066986fe65e2be2773d5c65b823bd6fece86
```

用户从 Finder 将两个普通文件真实拖入远程文件列表，原生队列均完成，远程目录出现
对应文件。再次拖入相同两文件，分别选择保留两份，生成 `finder report (1).txt` 和
`finder-alpha (1).txt`。源文件、远端原件及对应副本的大小和 SHA-256 一致：

| 源文件 | 字节 | SHA-256 |
| --- | --- | --- |
| `finder report.txt` | 130 | `c8373ebe80241999037d350d486245dff6beecc1c434736eef428218d4fa4a28` |
| `finder-alpha.txt` | 128 | `c62d019756fd5df6e9e2bdedc833cc4fd7093462d1f91df79a8175c51c17f368` |

远端目标目录没有 `.fileworker-*` 临时文件或备份遗留。该证据不是浏览器模拟事件、
直接调用上传 IPC 或应用双栏内部拖动。

## 同名自动弹框

本次源码的 macOS debug `.app` 使用相同隔离服务，通过原生上传按钮提交两文件，
不以此替代 Finder 入口验收。实测首个真实同名自动弹框，保留两份后自动提示第二个；
第二个关闭后保持待处理，刷新目录未重弹；从队列重新打开并保留两份成功。
生成的 `(2)` 副本与上表对应源文件 SHA-256 一致，原件未变，无临时文件遗留。

自动化补充：完整 `107` 项前端测试、`19` 项 Playwright、类型检查及生产前端构建通过。
覆盖关闭按钮、Escape、遮罩、重复快照、多个冲突、延后处理、重复点击、提交失败、
断开和新尝试、其他弹窗阻塞；检查明暗主题的 1280、800、390 像素视口。

