## FileWorker v0.1.0-preview.3

免费签名修复预发布，仅提供 macOS Apple Silicon（`arm64`）的 `.app.zip`。
推荐替代浏览器下载后可能报“已损坏”的 `preview.1`、`preview.2`。

### 本次修复

- 使用 Tauri 对可执行文件和完整 `.app` 执行 ad-hoc 临时签名，补齐资源封装与应用标识绑定。
- 打包前严格校验应用签名、标识、基础版本和架构；ZIP 完整性与解压后的签名再次校验。
- 自动生成 SHA-256，拒绝覆盖已有发布输出或向输入应用内写入；并发占用时保留对方目录，
  失败清理自身临时文件。
- 不改变 SFTP、传输队列、同名冲突、连接配置或凭据格式，不需要数据迁移。

### 下载与首次打开

1. 下载 ZIP 与同名 `.sha256` 文件，在下载目录运行：

   ```bash
   shasum -a 256 -c FileWorker-v0.1.0-preview.3-macos-arm64.app.zip.sha256
   ```

2. 校验成功后解压，将新包中的 `FileWorker.app` 放到应用程序目录。
3. 这不是 Developer ID 签名或 Apple 公证；系统仍可能要求单独允许打开。
   确认来自本仓库且校验一致后，在「系统设置 → 隐私与安全性」查找「仍要打开」，
   由本人确认。若没有入口或仍提示损坏，请反馈具体提示，不要关闭系统整体安全检查。

完整 ad-hoc 签名只修正签名封装，不保证无提示双击运行，不代表 Apple 审核或背书。
旧标签与附件保留，不在原版本下静默替换二进制。

### 验证与限制

- 本轮 `11` 项 macOS 打包回归、`107` 项前端测试、`19` 项 Playwright、
  `30` 项默认 Rust 测试、类型、格式与 Clippy 通过，优化构建通过。
- 优化应用和 ZIP 解压应用的严格签名校验通过；本机构建应用可显示文件列表，
  保持未连接、空队列并正常退出。这不替代浏览器下载后的首次启动验收。
- Chrome 实际下载的 ZIP 与发布附件 SHA-256 一致；Finder 解压成功，下载隔离标记
  保留，解压应用严格签名校验通过。下载后首次启动仍等待用户现场确认。
- 下载后首次启动与系统授权结果单独记录，不把本地直接启动或 `codesign` 成功
  视作 Gatekeeper 信任通过。未公证的 `spctl` 拒绝属于预发布边界。
- 已有 Finder 普通文件、混合无效批次与正常对照的原生证据见仓库验收记录；
  本轮未重跑真实协议、Keychain 或 ASan，不扩展这些测试的覆盖结论。
- 最低系统元数据仍为 macOS `12.0`，实际验收环境为 macOS `26.5.2`；
  Windows、Linux、Intel Mac 和 macOS 12 尚未实测。
- Finder 错误投放目标仍待原生验收；Finder 拖出、目录递归、暂停/续传、
  跨重启队列恢复仍未实现。不是正式稳定发行版。

### 回退

先结束传输并退出应用。连接配置无需迁移，已经传输的文件不会自动回滚。
旧预发布包有已知签名封装问题，不推荐作为可正常下载安装的回退方案；
需要回退功能时可从旧标签自行构建。
