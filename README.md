# FileWorker

面向 macOS 的开源双栏 SFTP 文件工具，使用 Rust、Tauri 2 和 React 构建。
并排浏览本地与远程目录，安全连接服务器，批量上传下载并跟踪每项任务的进度。
当前为第三阶段开发版，支持安全连接 SFTP、双栏浏览、普通文件上传下载和真实传输队列。
Finder 拖拽、目录递归传输和断点续传仍未实现。

## 项目状态

项目处于开发阶段，目前提供源码，尚未发布可下载的正式 Release。
已验收平台为 macOS Apple Silicon；其他平台和 Intel Mac 尚未验收。
开发版 `.app` 未进行 Developer ID 签名与公证，不应当作正式发行版分发。

后续先完善已确认设计中的拖拽工作流，再推进暂停/恢复和断点续传。
公开下载的 macOS 安装包、构建自动化、签名与发布验收见
[发布计划](docs/RELEASING.md)。该文档只是计划，不代表已有对应功能或 Release。

## 当前可用

- 真实本地目录浏览、路径输入、返回上级和原生目录选择。
- 按名称、大小、修改时间排序，筛选当前目录，切换隐藏文件。
- 新建、编辑、复制和删除 SFTP 连接配置。
- 配置原子写入，跨进程事务锁保护，拒绝密码和私钥口令等未知字段。
- SFTP 先握手并显示 SSH SHA-256 主机指纹；首次连接必须明确确认，
  已信任主机指纹变化时阻止连接。
- 密码认证和加密/未加密 SSH 私钥认证；认证成功后可选择保存私钥口令或密码到
  macOS 钥匙串，也可以从连接菜单忘记已存凭据。
- 远程目录浏览，支持进入目录、路径输入、返回上级、刷新、筛选、排序和隐藏文件。
- 勾选、范围及键盘多选普通文件，上传到右栏目录或下载到左栏目录。
- 真实后台传输队列，显示字节进度、平均速度、预计剩余时间、状态、错误和清理警告。
- 单项取消、失败/取消后从头重试；同名文件必须选择跳过、覆盖或保留两份。
- 默认同时传输 3 项，可调整为 1 到 6 项；每项使用独立且重新校验指纹的 SSH 连接。
- 网络操作有超时，待认证连接会主动过期关闭；支持取消、断开和迟到响应隔离。
  网络、认证和目录错误会显示给用户，不会伪装成空目录。
- 中文双栏界面、侧栏、传输区折叠和窄视口文件栏切换。
- 深色、浅色、跟随系统三种外观，自动保存选择，统一适配表格、菜单和弹窗。
- macOS 本地开发及 `.app` 打包。

暂停恢复、自动重试、断点续传、跨重启队列恢复、Finder 拖拽、目录递归传输及远程
新建/删除/重命名工具属于后续阶段。

## 上传与下载

1. 连接服务器，并在双栏分别打开本地目录和远程目录。
2. 勾选文件，点击本地栏的上传图标，或远程栏的下载图标。目标是另一栏最后成功打开
   的目录，不是尚未提交的路径输入。目录和符号链接不能作为本阶段的传输来源。
3. 使用复选框多选，或在行上使用 Shift 范围选择、Command/Ctrl 切换选择；
   方向键移动选择，空格切换文件选择，Command/Ctrl+A 选择当前可见的普通文件。
   筛选或切换目录会清理不可见的选择，避免意外传输。
4. 在队列查看进度和失败原因。遇到同名文件，点击该任务的处理图标，再明确选择
   「跳过」「覆盖」或「保留两份」；保留两份使用 `文件名 (1).扩展名` 等新名称。
5. 使用每行取消或重试图标。取消发生在分块读写边界，阻塞网络操作需等到返回或超时，
   不会切断浏览连接。若最终提交已经开始，任务仍可能完成。重试从头传输，重新检查同名文件，
   不自动覆盖，也不是断点续传。断开、切换或编辑连接后，旧任务不能在新会话中重试。

完成后会刷新仍在查看的目标目录；如果该目录正在读取，等读取结束后再补刷，
不会覆盖已经切换的目录或尚未提交的路径输入。

传输先写入目标目录内的随机 `.fileworker-*.part` 临时文件，校验长度并关闭后才提交。
默认提交使用不覆盖语义，即使目标在传输途中出现，也不会静默覆盖。
本地明确覆盖通过同目录临时文件替换；远程明确覆盖先将原文件改名为随机
`.fileworker-*.backup`，再提交新文件，失败则尝试恢复原件。远程覆盖不是无间隙原子替换，
短暂缺少目标路径，断网或断电可能留下备份。恢复或清理失败会显示具体路径，
请重新连接后检查；应用不会先删除原文件，也不会自动删除不明临时文件。
有其他进程同时修改目标时，排他提交失败会保留现有文件，必要时保留原文件备份供人工恢复。

正常取消或失败会清理临时文件；网络已中断、强制退出、系统崩溃时无法保证远程清理。
新上传和下载文件默认权限为 `0600`，不复制原权限、修改时间或扩展属性。
源文件大小或修改时间在传输中发生变化会拒绝提交，但不提供源文件快照或内容哈希校验。
本阶段不递归复制文件夹、不跟随源符号链接、不覆盖目录或特殊文件。

队列只保存在当前进程内，每批最多 256 项，总计最多 1000 项。并发设置同样只在本次运行有效；
降低并发不强行中断已经运行的任务。清理已结束任务只删除队列记录，不删除已传输文件。
正常退出会停止调度、取消未结束任务并等待工作线程清理；下次启动不恢复任务。

## SFTP 连接

1. 在桌面应用中点击「新建连接」，填写主机、端口、用户名、认证方式和默认远程目录。
   私钥文件可使用绝对路径或 `~/` 开头的路径；默认远程目录 `.` 表示服务器主目录。
2. 点击「连接服务器」。新主机先显示指纹，请通过可信渠道向管理员核对，再点击
   「信任并继续」。已保存指纹发生变化时会阻止连接，不能直接覆盖旧记录。
3. 输入密码或私钥口令。未加密私钥的口令可留空；勾选「使用已保存的凭据」会由
   Rust 从 macOS 钥匙串读取，不会将已存秘密返回界面。
4. 成功后在右栏浏览目录。相对路径以最后成功打开的目录为基准，符号链接与 `..`
   由服务器解析；空路径提交刷新当前目录。无权限时显示错误，仍可返回上级或重试。
5. 点击断开图标结束会话。连接菜单中的「忘记已存凭据」只删除该认证身份对应的
   钥匙串条目，不删除配置、主机信任记录或服务器文件。

默认网络操作超时为 15 秒，待认证连接有效期为两分钟。等待钥匙串授权时也可能过期，
过期后需重新连接；同一凭据的操作保持串行，另一配置不会被旧授权提示锁住。
保存失败不会中断已认证的连接。保存尚未提交为有效会话便被取消时，会恢复原有凭据；
系统拒绝恢复时会返回说明。已完成的保存或主机信任不会因之后断开而自动忘记。
当前仅支持密码和私钥认证，不支持 SSH Agent、键盘交互式认证或多因素认证。

## 外观

点击右上角的外观图标，选择「深色」「浅色」或「跟随系统」。
首次打开默认跟随系统；手动选择后，系统变化不会覆盖选择，重新启动也会恢复。
深色采用石墨灰面板，青绿突出主操作、蓝色区分远程区域，文件夹使用琥珀色。
浅色版同时加深文字和边框；界面布局和文件操作方式保持不变。

偏好单独保存在当前应用的 WebView 本地存储中，键为
`fileworker.appearance.v1`，值为 `light`、`dark` 或 `system`，
不写入连接配置文件。浏览器预览与桌面应用分别保存选择。
本地存储不可用时仍可在当前会话切换，并显示保存失败提示。
页面通过本地 `public/theme-init.js` 在 React 加载前恢复背景与配色，
无需放宽脚本内容安全策略；桌面应用还会同步自身的原生窗口主题，不修改系统外观。

## 启动

先安装下方列出的 Rust、Node.js、pnpm 及 macOS 编译工具，再获取源码并安装前端依赖：

```bash
git clone https://github.com/wyzerg/FileWorker.git
cd FileWorker
bash scripts/run.sh install --frozen-lockfile
```

在项目根目录执行：

```bash
bash scripts/run.sh desktop
```

启动脚本自动定位本项目使用的工具链，不需要先修改终端环境变量。
桌面开发服务器使用 `127.0.0.1:1420`。

仅预览界面：

```bash
bash scripts/run.sh dev --port 1430
```

浏览器预览不能读取真实本地目录。预览中的连接配置只保存在浏览器本地存储，
不会同步到桌面应用，也不会尝试连接服务器。

## 配置与安全

桌面连接配置位于：

```text
~/Library/Application Support/com.fileworker.desktop/profiles.json
```

数据结构为 `{ "version": 1, "profiles": [...] }`。
配置模型不含密码字段；前端输入的密码和私钥口令只通过认证参数传给 Rust，
Rust 不将秘密返回前端或写入配置。
为独立传输连接复用认证，Rust 在活动会话内存中以 `Zeroizing` 保留本次密码或私钥口令，
不要求保存到 Keychain。断开立即使会话失效；正在认证的线程释放最后引用后会零化秘密。
忘记已存凭据只移除 Keychain 条目，不使当前已认证会话失效。
损坏、包含未知字段或版本不受支持的配置会报错，不会被静默重置。
新建目录权限为 `0700`，配置文件权限为 `0600`。
配置读改写事务由同目录 `profiles.lock` 文件锁串行化，防止多个实例互相覆盖新增连接。
锁文件不保存凭据；进程退出后由操作系统释放锁。
多个窗口不会实时同步列表，需要重新打开应用才能重新读取其他实例的改动。

本地浏览只读取目录；只有主动提交的下载任务才创建文件，明确选择覆盖后才替换已有文件。
遇到目录访问错误会显示错误；个别文件信息读取失败会显示警告数量。

远程主机信任记录单独保存在应用数据目录的 `known_hosts.json`，不使用也不修改用户的
`~/.ssh/known_hosts`。应用专用记录使用主机名和端口区分，写入前通过锁文件串行化并
使用临时文件替换；损坏记录不会被静默覆盖。macOS 凭据服务只访问
`com.fileworker.desktop.credentials.v1` 服务下、由连接配置和认证身份计算出的条目。
条目绑定配置 ID、主机、端口、用户名、认证方式和私钥路径；改名或默认目录不改变绑定。
修改认证身份或删除配置前可先忘记凭据，删除配置本身不会自动删除旧钥匙串条目。
凭据协调限定于单个应用进程，不支持多实例并发修改同一凭据。
浏览器预览不会发起 SSH、读取本地钥匙串或保存密码。

`Cargo.toml` 将 `libssh2-sys` 固定到 `ssh2-rs` 上游提交
`60b9c193bcf0511aa569d1408a92fd3ba803f4b7`，修复服务端重复签名算法触发的 C
堆越界；不要在未运行相应协议回归与 C AddressSanitizer 检查时移除该固定。

## 验证与打包

```bash
bash scripts/run.sh test
bash scripts/run.sh typecheck
bash scripts/run.sh build
bash scripts/run.sh exec playwright install chromium
bash scripts/run.sh test:e2e
source "$HOME/.cargo/env"
cargo test --workspace
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
bash scripts/run.sh tauri build --debug --bundles app
```

开发版应用生成到 `target/debug/bundle/macos/FileWorker.app`。
此版本未进行 Developer ID 签名与公证，尚不用于对外发布。
Rust 验证与 Tauri 打包请依次执行，避免不同构建环境在共享 `target` 中干扰文档测试。

真实协议测试默认标为 `ignored`，需另行执行。它只启动监听 `127.0.0.1` 的临时
AsyncSSH 服务并生成测试密钥，不开启系统 SSH 服务、不访问用户密钥：

```bash
python3 -m venv target/sftp-test-venv
target/sftp-test-venv/bin/python -m pip install 'asyncssh==2.21.1'
source "$HOME/.cargo/env"
cargo test -p fileworker-core --test sftp_integration -- --ignored --nocapture
cargo test -p fileworker-app keychain_roundtrip_and_delete_use_an_isolated_random_account -- --ignored --nocapture
```

已有 Python 测试环境可通过 `FILEWORKER_TEST_PYTHON` 指定解释器。Keychain 测试仅适用于
macOS，创建一个随机测试条目并在结束时清理。C AddressSanitizer 需实际对 C 依赖加
`-fsanitize=address`，仅运行普通 Rust 测试不能替代；本轮编译与运行方式记录在第二阶段计划中。

第三阶段的验收记录保存在
`docs/superpowers/plans/2026-11-04-file-transfers-plan.md`，包含文件内容校验、同名决策、
目标竞争、回滚、取消清理、源变化、并发限制、退出以及原生应用测试范围。
本轮已通过 27 项默认 Rust 核心测试、21 项 C AddressSanitizer 真实协议测试、
单独执行的 21 项真实协议测试、50 项前端测试、9 项 Playwright 测试、类型检查、
Rust 格式检查和 Clippy；生产前端与开发版 `.app` 构建通过。原生应用已实测上传/下载、
同名保留两份、64 MB 文件取消与从头重试，并核对生成文件的 SHA-256。
最后一次刷新修复后已重打包并退出重开，确认本地浏览、断开状态和空队列正常。
未验证外部服务器或 Windows/Linux 打包。Finder 原生拖拽、断点续传和目录递归传输仍待后续验收。
